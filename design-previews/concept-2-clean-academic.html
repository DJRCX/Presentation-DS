Attribute Types

ER Attribute Taxonomy

Illustrated using the PATIENT entity as example.

Key Attribute
Patient_ID
Uniquely identifies each patient. Underlined in standard ER notation. Always NOT NULL and UNIQUE.
Patient_ID VARCHAR(20) PK UNIQUE NOT NULL
Composite Attribute
Address
Can be divided into smaller sub-components, each meaningful on its own.
Address -> House_No, Street, City, Postal_Code
Multivalued Attribute
Phone_Number
A patient may hold multiple phone numbers. Stored in a separate table to comply with 1NF.
Patient_Phone(Patient_ID FK PK, Phone_Number PK)
Derived Attribute
Age
Calculated from Date_of_Birth at query time. Not physically stored to prevent stale data.
Age <- DATEDIFF(NOW(), Date_of_Birth) / 365

Business Rules & Conclusion

Business Rules

Core constraints governing the integrated healthcare system.

01One hospital can have many departments. Each department belongs to one hospital.1:N
02A doctor can work in multiple departments; a department can have multiple doctors.M:N
03A patient can make multiple appointments; each appointment links to one patient and one doctor.1:N
04A patient can be admitted multiple times, each admission to a specific ward in a hospital.1:N
05One prescription can contain multiple medications (M:N resolved via Prescription_Medicine).M:N
06A hospital manages multiple ambulances; each ambulance handles multiple dispatches over time.1:N
