attributes / taxonomy

Attribute Types

Demonstrated via the PATIENT entity.

// Key Attribute
Patient_ID
Uniquely identifies each patient. Underlined in ER notation. NOT NULL + UNIQUE.
Patient_ID VARCHAR(20) PK UNIQUE NOT NULL
// Composite Attribute
Address
Divisible into smaller components each with independent meaning.
Address -> { House_No, Street, City, Postal_Code }
// Multivalued Attribute
Phone_Number
A patient can have multiple phones. Stored in a separate table (1NF compliance).
Patient_Phone(Patient_ID FK PK, Phone PK)
// Derived Attribute
Age
Computed from Date_of_Birth. Not physically stored; derived at runtime.
Age <- FLOOR(DATEDIFF(NOW(), DOB) / 365)

rules / conclusion

Business Rules

Core constraints governing the integrated healthcare database system.

->One hospital has many departments. Each department belongs to one hospital.1:N
->Doctor works in multiple departments; a department has multiple doctors.M:N
->Patient makes multiple appointments; each links to one patient and one doctor.1:N
->Patient can be admitted multiple times; each admission assigned to one ward.1:N
->One prescription contains multiple medications (M:N via Prescription_Medicine).M:N
->Hospital manages multiple ambulances; each ambulance handles multiple dispatches.1:N
