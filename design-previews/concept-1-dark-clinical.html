06 — Attribute Types

ER Attribute Taxonomy

Demonstrated using the PATIENT entity.

Key Attribute
Patient_ID
Uniquely identifies every patient record. Underlined in ER notation.
Patient_ID PK — UNIQUE, NOT NULL
Composite Attribute
Address
Decomposed into sub-attributes: House_No, Street, City, Postal_Code.
Address -> House_No, Street, City, Postal_Code
Multivalued Attribute
Phone_Number
A patient may have multiple phones. Stored in a separate Patient_Phone table.
Patient_Phone(Patient_ID PK FK, Phone_Number PK)
Derived Attribute
Age
Computed from Date_of_Birth at query time. Not stored directly.
Age <- DATEDIFF(NOW(), Date_of_Birth)

11 — Business Rules & Conclusion

Business Rules

Core constraints derived from the healthcare scenario.

One hospital can contain many departments. Each department belongs to exactly one hospital. [1:N]
A doctor can work in multiple departments; a department can have multiple doctors. [M:N]
A patient can make multiple appointments, each linked to one doctor. [1:N]
A patient can be admitted multiple times, each assigned to a specific ward. [1:N]
One prescription can contain multiple medications (M:N via Prescription_Medicine). [M:N]
A hospital owns multiple ambulances; each ambulance handles multiple dispatches. [1:N]
Our database integrates patient care, hospital operations, medical services, insurance, and ambulance support into a single relational system.
